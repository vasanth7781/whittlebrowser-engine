Open source · Chromium · MCP server

The browser AI agents can afford, and you can trust.

WhittleBrowser shows web pages to LLMs as compact, ref-stable text and sends only what changed after each action. That's 96% fewer tokens than Playwright MCP. Secrets and hidden prompt injections never reach the model, and you can watch every move it makes.

Use it with Claude, Cursor, Codex Watch it work ↓

Coming soon Download for Mac: a light, agentic browser. Until then, use the open-source engine with your own AI tools.

    Act, then see only what changed
    
    Batch the steps. Get back a diff.
    
    
    Fill a whole form in one call. Instead of the whole page again, the model gets an outcome line per step and a diff: ~ changed, + added, − removed, @ where. Refs stay stable even when React re-renders the page.
    
    
      
      
    • Hit-test before every click: "covered by dialog 'Cookies'", never a blind click
      • 
      
    • Navigation, new tabs, dialogs and downloads reported
      • 
      
    • If a diff would cost more than the page, you get the page
      •

    Benchmark
    
    Four tools. Same pages. Real tokens.
    
    
    We ran WhittleBrowser, Playwright MCP, browser-use and Stagehand on the same 11 pages (5 test pages and 6 live sites) with the same Chromium, and counted exactly what each one puts in front of the model. No LLM calls, so nothing is estimated except screenshot tokens.
    
  
    
  
  
  
  
  
    
    
    Same pages, same browser
    Every tool loads the same 11 URLs in the same Chromium build at 1280×860. Fixture pages are served locally so results are repeatable.
    
    
    Each tool's own code
    Playwright's ariaSnapshot (what Playwright MCP returns), browser-use's AgentMessagePrompt, Stagehand's page.snapshot() and its act prompt builders. Nothing re-implemented.
    
    
    Exact text, counted
    We capture the exact text each tool builds and count it with the o200k tokenizer. Run it yourself: pnpm bench -- --live --pw-mcp. Full methodology →

    X-ray · ⌘⇧X
    
    See the page through the agent's eyes.
    
    
    X-ray draws the agent's view on the real page: every control it can use with its ref, fields masked from AI, and the text it was not shown: white-on-white, 1px fonts, off-screen tricks. That hidden text is how agentic browsers have been hijacked.

    •  Sensitive fields, masked from the model
      • 
      
    •  Hidden text withheld from the model
      • 
      
    •  Visible text that reads like an injection, flagged ⚠

    Ghost cursor · live steps
    
    Watch it work. Stop it any time.
    
    
    Before every click or keystroke, a cursor glides to the target, a ring highlights it, and a caption says what's about to happen. The Agent panel streams each step, and every entry expands to show exactly what was sent to the model and how many tokens it cost.
    
    
      
      
    • Risky actions (pay, delete, send, publish) wait for your click
      • 
      
    • CAPTCHAs and 2FA are handed to you, then the agent resumes
      • 
      
    • One click turns AI off for a site

    Works on real-world markup
    
    Div soup in. A clean page out.
    
    
    Most modern apps are <div>s with click handlers: no buttons, no nav, no header tags, modals built from overlays. WhittleBrowser finds the real handlers (including React onClick props) and infers headers, sidebars, footers, menus and dialogs from layout and naming. The model sees a page it can act on.

    Safety model
    
    Pages are hostile. Your secrets stay home.
    
  
    
  
    
    
    AI off by default
    Off, Ask or Allowed per site. Nothing is sent from sites you haven't allowed.
    
    
    Auto-pause
    Banks, cloud consoles, password managers and card/ID/API-key fields pause AI automatically.
    
    
    Secrets never leave
    Field values are masked in the page. Keys and cards become ‹tokens›. Vault refs are typed locally.
    
    
    Injection shield
    Hidden text is dropped before the model sees the page. Instruction-like text is flagged.
    
    
    Approvals
    Pay, delete, send, publish, cross-site data jumps and uploads need your OK.
    
    
    Isolated agent
    Runs in a CDP isolated world, so page scripts can't tamper with what it sees.
    
    
    Honest identity
    UA token, Web Bot Auth signatures (verified with Cloudflare's checker), robots.txt. No spoofing, no CAPTCHA solving.
    
    
    Light on RAM
    Tab Sleeper freezes and discards background tabs within a memory budget; a meter shows per-tab MB.

    Quick start
    Two minutes to your first agent run.
    
  
    
    
    
      
    
    
    
    # install (from source, once)
git clone https://github.com/vasanth7781/whittlebrowser-engine.git && cd whittlebrowser-engine
pnpm install && pnpm --filter @whittlebrowser/engine build
npx playwright-core install chromium

# connect Claude Code (once, from the repo root)
claude mcp add whittlebrowser -- node "$PWD/packages/engine/dist/mcp/cli.js" --show-cursor

# then ask Claude:
"Use whittlebrowser to research the top 5 results and compare them."
    
    
    # no window, throwaway profile: for CI and servers
claude mcp add whittlebrowser -- node "$PWD/packages/engine/dist/mcp/cli.js" --headless --ephemeral
    
    
    pnpm test                        # unit, browser, MCP, canary leak tests
pnpm bench -- --live --pw-mcp    # tokens, leaks, injections vs Playwright MCP
pnpm bench:agent --smoke         # real-agent run through Claude Code (needs the claude CLI)
